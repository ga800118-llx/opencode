# Guai Code Beta 问题记录

## GC-001 自动批准模式无法启用

- 记录日期：2026-08-22
- 影响范围：当前 Mac 内部测试版本
- 状态：已修复，待人工验收
- 优先级：高

### 复现步骤

1. 打开一个任务。
2. 打开权限模式选择器。
3. 选择“自动批准”。

### 实际结果

界面提示“无法更改权限模式”，自动批准模式没有生效。

### 预期结果

在当前本地服务支持权限模式的情况下，应当能够切换到“自动批准”，并在当前任务中立即生效。

### 根因

- 本地 V2 服务已经公开权限模式接口，但桌面前端使用的旧版 Promise 客户端没有 `switchPermissionMode` 方法。
- 兼容层通过类型断言掩盖了运行时方法缺失，导致点击后在前端直接失败，请求没有到达服务端。
- 前端在请求前写入项目默认模式，失败后没有恢复，形成项目默认值和当前任务状态不一致。

### 修复

- V2 权限模式切换通过同一连接的生成 SDK 调用 `/api/session/:id/permission-mode`。
- 移除权限状态中的运行时方法断言。
- 最新一次切换失败时恢复原项目默认模式，当前任务继续使用服务端确认的模式。
- 保留队列切换、跨窗口事件和服务端仍处于 Auto 时的待审批恢复行为。

### 自动验证

- V1、V2 权限兼容和状态测试通过。
- 服务端权限接口与持久化测试通过。
- 应用类型检查和生产构建通过。

## GC-002 工具调用期间耗时停止增加

- 记录日期：2026-08-22
- 影响范围：任务时间线
- 状态：已修复，待人工验收
- 优先级：中

### 实际结果

普通对话的耗时持续增加，但进入工具调用后，耗时会停在某个中间值，直到后续消息完成才变化。

### 根因

运行中的一次任务可能包含多条 Assistant 消息。原实现只要发现一条中间消息已有完成时间，就提前使用该时间固定整个任务的耗时。

### 修复

- 任务仍在运行时始终使用当前时间减去用户消息创建时间。
- 任务进入空闲状态后才使用最后一条有效 Assistant 完成时间固定耗时。
- 将计算提取为纯函数并覆盖运行中、已完成和无效时间戳测试。

## GC-003 新配置默认模型需要再次设置才出现在任务中

- 记录日期：2026-08-22
- 影响范围：私有模型配置、Sidecar 重连、任务模型选择器
- 状态：已修复，待人工验收
- 优先级：高

### 实际结果

添加私有模型并设为默认后，新任务偶尔没有可选模型；再次设置同一默认模型后恢复。

### 根因

模型配置会重启或重新加载 Sidecar。配置操作完成后的前台刷新可能与自动 `server.connected` 刷新重叠，并直接复用一轮较早开始的刷新，因此界面可能保留旧模型目录。

### 修复

- 普通后台刷新继续合并，避免重复请求。
- 模型保存、删除和设为默认使用 `fresh` 刷新语义；若已有刷新在运行，则在其结束后启动一次尾随刷新。
- 同一轮并发关键刷新共享一个尾随请求；前一轮失败也不会阻止尾随刷新。

### 人工验收

1. 新增一个私有模型源并保存。
2. 选择其中一个模型作为默认模型。
3. 不重启应用、不重复设置默认模型，直接新建任务。
4. 确认任务模型选择器立即显示该模型并可正常对话。
5. 在工具调用过程中观察耗时持续增加。
6. 在同一任务切换到自动批准，确认模式立即生效且不再出现“无法更改权限模式”。
