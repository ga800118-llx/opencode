# Mac 稳定性与易用性修复设计

## 目标

一次性修复当前 Mac 桌面端的五类问题，并用自动化测试、真实 Mac 回归和安装包冒烟共同证明修复有效：

1. 模型执行不再被用户配置的 30 秒或其他总时长超时中断；系统能区分持续活动、响应缓慢和无法确认活动三种状态。
2. 项目名称、图标颜色和启动命令可以可靠保存，V1 与 V2 服务器行为一致且没有静默失败。
3. 上下文入口和详情不再显示成本，详情中提供“压缩上下文”操作。
4. 新安装的 Skill 无需重启或刷新整个应用即可出现在 Skill 页面。
5. 新增项目后可以立即新建任务；项目尚未就绪时应用等待初始化，失败时可以直接重试。

本轮采用“方案 B”：保留现有 Solid store、TanStack Query、Server Sync 和标签页体系，只增加明确的运行活动、工作区就绪和资源刷新边界。不重做整个前端状态系统。

## 已确认根因

### 模型超时

- 模型中心默认把 `timeoutMs` 设为 30 秒，并允许用户编辑。
- 同一个值同时控制模型发现/能力测试、凭据代理 socket 超时和完整模型请求总时长。
- Provider 运行时把该值转换成 `AbortSignal.timeout(...)`。即使模型仍在生成或工具任务仍在运行，到达总时长也会中断。
- 用户调大该值后任务成功，说明完整请求总时长是当前故障的直接原因。

### 项目保存

- 编辑项目和侧边栏重命名遇到 V2 协议时直接 `return`，没有保存、错误或用户反馈。
- 本地 `projectMeta` 已能持久化名称、颜色和启动命令，但项目列表的合并逻辑没有读取这些字段。
- 自动分配颜色也只在 V1 写回服务器，V2 直接跳过。

### Skill 刷新

- Skill 页面只在查询首次挂载和页面内启用、禁用、删除后刷新。
- Agent、CLI 或其他进程在文件系统中安装 Skill 时，没有查询失效事件。
- 现有空列表重试只处理冷启动，不能处理“已有列表中缺少刚安装 Skill”的情况。

### 新项目后立即新建任务

- 新项目先乐观写入本地项目列表，再异步启动目录 bootstrap 和 session 加载。
- 新建任务会立即创建 draft 并导航，未等待目录的项目、配置和 provider 状态可用。
- 重启后异步初始化已经完成，所以同一操作恢复正常。

### 上下文成本与压缩

- 圆形上下文入口的 tooltip 和上下文详情分别格式化并显示 USD 成本。
- `/compact` 和 `session.compact` 已存在，但上下文详情没有可视化入口。

## 架构决策

新增三个小型机制，不建立新的全局状态框架：

1. **Activity Watchdog**：记录会话最后一次有意义的活动，并把运行状态投影为“活动中、响应缓慢、活动未确认”。它只负责状态判断和提示，不负责终止任务。
2. **Workspace Readiness**：为每个 server + directory 提供可等待、可去重、可重试的初始化 Promise。创建 draft 前必须通过该边界。
3. **Resource Invalidation**：Core 重新扫描 Skill 来源，前端在页面打开、窗口恢复和短周期可见轮询时重新读取资源，并提供手动刷新。页面内变更继续主动失效查询。

这些机制均建立在现有数据源之上，不复制会话、项目或 Skill 的权威数据。

## 一、系统托管的模型运行策略

### 配置与兼容

- 从模型配置界面删除用户可编辑的超时字段。
- 新保存的模型源不再持久化运行总时长。
- 读取旧模型源时允许存在 `timeoutMs`，但把它作为遗留字段丢弃，不再控制运行请求。
- 模型发现和能力测试使用系统内部常量，首版为 30 秒；本地服务探测继续使用更短的内部时间。用户不需要理解或调整这些值。

### 运行请求

- 私有 OpenAI-compatible 模型配置显式关闭完整请求总时长和响应头总时长限制。
- 不为运行时 SSE 设置“到点即中断”的 chunk 总时长。
- 凭据代理不再复用探测超时中断模型流。
- V1 Provider、Core AISDK 和 V2 `packages/llm` 三条模型执行链路都必须应用同一策略，超时字段不能进入 V2 模型请求 body。
- 请求只在以下情况结束：模型正常完成、网络/上游返回明确错误、底层连接明确断开、应用关闭，或用户主动停止。
- 工具调用失败作为结构化结果返回会话，由 Agent 决定恢复、重试或解释；单个工具失败不等同于整个任务超时。

### 活动判断

会话状态存储记录最后一次有意义的活动时间。以下事件会刷新活动时间：

- assistant 消息、推理或文本增量；
- 工具开始、进度、输出和结束；
- 会话执行、重试、权限和问题状态变化；
- 明确的 provider 或网络事件。

Watchdog 的投影规则固定为：

- `active`：最近 3 分钟内有事件，或存在已知仍在运行的工具/命令；
- `slow`：会话仍为 busy，但 3 至 10 分钟没有可观察事件；
- `unverified`：会话仍为 busy，且超过 10 分钟无法观察到活动；
- `idle`：会话已完成、失败或被用户停止。

`slow` 和 `unverified` 只改变处理过程区域的文案。`unverified` 明确显示“暂时无法确认模型活动，任务仍在继续”，不暂停任务，也不要求用户点击“继续”。现有停止按钮始终可用。

运行超过 60 分钟不是异常条件。若工具或输出仍有活动，状态持续为 `active`；即使无法确认活动，也只提示并继续等待。

### 性能承诺口径

- 产品不设置任务总运行时长上限。
- 自动化测试用虚拟时间证明持续活动 8 小时不会触发应用中止。
- 发布前在打包后的 Mac 应用执行至少 65 分钟真实持续运行冒烟，跨过用户要求的 60 分钟边界。
- 上游服务自身的配额、负载均衡或连接限制不属于应用可承诺的运行时长，但其明确错误必须原样转为可理解的产品错误。

## 二、项目元数据保存

### 数据优先级

项目展示数据按以下顺序合并：

1. server 返回的项目元数据作为基础；
2. 本地 `projectMeta` 覆盖名称、图标颜色、图标 override 和启动命令；
3. 本地项目列表只提供 `worktree` 和展开状态，不覆盖元数据。

图标对象使用字段级合并，避免只改颜色时丢失 URL 或自定义图片。

### 保存行为

- V1：先调用现有项目更新 API；成功后同步 server project store，并写入本地 `projectMeta` 作为一致的 UI 镜像。
- V2：当前协议没有可用的 project update API，因此直接写入持久化 `projectMeta`。
- global/仅本地项目：继续写入 `projectMeta`。
- 侧边栏重命名、编辑弹窗和自动颜色分配复用同一套持久化规则，不再各自判断协议后静默返回。
- 保存期间按钮显示进行中并防止重复提交；成功后才关闭弹窗。
- 失败时弹窗保持打开并显示可理解的错误，用户可以直接重试。

保存后立即更新当前窗口；关闭应用重新打开后名称、颜色和启动命令仍保持。

V2 的本地 `projectMeta` 仅保证当前电脑持久化，不承诺跨电脑同步。未来若需要跨设备项目元数据，必须新增服务端协议，本轮不隐含该能力。

创建 Git worktree 时，V1 继续使用服务器现有项目配置；V2 在公开的 Worktree create 请求中增加可选 `projectStartCommandOverride`，把当前电脑已持久化的项目启动命令传给工作区创建流程。该字段只影响本次创建，不承担项目元数据跨设备同步。由于这是公开协议变更，必须重新生成 OpenAPI 快照与 JavaScript SDK，禁止手改生成文件。

## 三、工作区就绪边界

`Workspace Readiness` 以 server scope 和规范化目录作为键，状态为：

- `initializing`：目录 bootstrap 正在执行；
- `ready`：项目身份、目录配置和 provider 数据已完成首次初始化；
- `degraded`：项目身份和目录配置已就绪，但 provider 等非关键资源失败；允许进入任务并引导用户检查模型配置；
- `failed`：初始化返回明确错误，可再次调用重试。

行为规则：

- 同一目录的并发初始化共享同一个 Promise，不重复请求。
- 新增项目仍可立即出现在列表中，但“新建任务”在后台等待 readiness。
- `tabs.newDraft(...)` 是统一门槛：所有首页、标题栏、会话页入口在真正创建 draft 和导航前都等待 readiness，避免遗漏某个按钮。
- 等待期间入口显示忙碌状态且不重复创建 draft。
- 只有项目身份、目录或必要配置失败才进入 `failed`。provider、历史会话或其他非关键资源失败进入 `degraded`，不能让整个任务页面崩溃。
- `failed` 时不创建空白或损坏的 tab，显示错误与重试提示；再次点击会启动新的初始化，不需要重启应用。
- 已就绪项目走同步快路径，不增加日常新建任务的可感知延迟。

目录 bootstrap 必须返回代表完整初始化结果的 Promise，不能在内部启动未被调用方等待的异步任务后提前完成。

## 四、Skill 列表刷新

Skill 刷新分为 Core 重新扫描和前端查询刷新两层。

Core 层：

- Skill 管理列表读取前重新加载来源拓扑，并重新扫描目录型来源；
- 对远程或其他非目录来源保留正常缓存，手动刷新时才清理相应缓存，避免每 2 秒重复网络拉取；
- 页面自动轮询至少能发现 Agent、CLI 或其他进程新写入的全局和项目目录 Skill；
- 优先在现有 management list 边界完成，不新增协议。如果现有接口无法表达“强制刷新”，再单独审查协议变更。

前端层：

- 页面每次挂载时读取；
- 窗口重新获得焦点或从隐藏恢复时读取；
- Skill 页面可见期间每 2 秒做一次轻量重新读取；
- 页面顶部提供带 tooltip 的刷新图标按钮；
- 页面内启用、禁用、删除成功后立即失效当前 scope + directory 的查询。

轮询只在 Skill 页面挂载且文档可见时运行，离开页面立即停止。页面自动轮询走本地轻量扫描，手动刷新可执行完整来源刷新。

刷新失败时保留上一次成功列表并显示错误，不把错误伪装成空列表。成功结果无论为空还是非空都替换缓存。冷启动的有限空列表重试继续保留。

验收必须覆盖全局 Skill、项目 Skill，以及由 Agent/CLI 在页面打开期间写入的新 Skill。

## 五、上下文显示与手动压缩

- 圆形上下文入口的 tooltip 只显示使用率和 token 数，不显示成本。
- 上下文详情移除“总成本”统计；后端成本数据暂不删除，避免影响其他兼容逻辑。
- 在上下文详情统计区域加入图标加文字的“压缩上下文”命令，使用现有 `session.compact` API。
- `/compact` 命令和按钮调用同一个前端 compaction 操作，统一模型缺失、请求中、成功和失败行为。
- 无会话、没有可压缩消息、没有当前模型或会话正在执行时按钮禁用，并通过 tooltip 说明原因。
- 请求中防止重复点击；成功后显示成功反馈并等待会话事件更新 token；失败时保留当前上下文并显示错误。

本轮不重新设计压缩结果展示，也不分析压缩中具体调用了哪些工具。

## 错误处理原则

- 禁止协议判断后的静默 `return`。不支持的操作必须选择本地兼容路径或显示明确错误。
- 异步状态只在实际 Promise 完成后进入成功；fire-and-forget 不能作为 readiness 证据。
- 自动刷新错误不清空最后一次成功数据。
- 运行活动提示绝不触发隐式中止。
- 所有重试均去重，避免连续点击产生重复 tab、重复保存或重复压缩。

## 测试与验收

### 自动化测试

模型运行：

- 旧 `timeoutMs` 可读取但不再序列化为运行总时长。
- 私有模型 provider 配置显式禁用完整请求和 header 超时。
- V1 Provider、Core AISDK 和 V2 LLM executor 均不引入运行总时限或把超时字段误传给模型 body。
- 凭据代理在持续流和长静默阶段不主动销毁上游请求。
- 发现/能力测试仍在内部 30 秒超时并返回清晰诊断。
- Watchdog 覆盖 `active`、`slow`、`unverified`、`idle`，以及虚拟 8 小时持续工具活动。

项目：

- 项目元数据字段级合并与优先级。
- V1 更新成功后 server store 与本地 meta 一致；V1 失败不关闭弹窗。
- V2、global 和本地项目保存后立即显示，并可从持久化状态恢复。
- 自动颜色在 V1/V2 均持久化。

工作区 readiness：

- 并发调用只执行一次 bootstrap。
- 初始化完成前不创建 draft，完成后只创建一个。
- 非关键 provider 失败进入 `degraded` 并可打开任务；关键目录失败进入 `failed`。
- 首次失败后再次点击可以成功，无需重启。
- 所有 `tabs.newDraft` 入口都经过统一门槛。

Skill：

- 首次空列表重试保持现有行为。
- 页面挂载、focus/visibility 和可见轮询触发刷新。
- Core 管理列表重新扫描本地来源，手动刷新清理需要更新的非目录缓存。
- 外部新增 Skill 后下一次轮询更新列表和数量。
- 页面卸载或隐藏后不再轮询。
- 刷新失败保留旧列表并显示错误。

上下文：

- tooltip 和详情 DOM 中不存在成本标签和值。
- 压缩按钮的禁用条件、单次提交、成功和错误状态。
- 按钮与 `/compact` 使用同一个操作并调用正确 sessionID/model。

### Mac 真实回归

在干净用户数据和从当前 alpha 版本升级两种环境分别验证：

1. 添加私有模型源，确认界面没有超时输入；执行超过 30 秒的模型响应和工具任务，不出现 `The operation was aborted due to timeout`。
2. 执行至少 65 分钟持续任务，确认跨过 60 分钟后有活动时仍不暂停；模拟长静默，确认只提示且任务继续。
3. 在 V1 与 V2 连接分别修改项目名称、颜色和启动命令，立即查看并重启应用复查。
4. 新增项目后不等待，立即点击“新建任务”，确认只打开一个可用任务；模拟初始化失败后直接重试。
5. 保持 Skill 页面打开，从 Agent/CLI 新装全局和项目 Skill，确认 2 秒级显示；再验证手动刷新。
6. 检查上下文圆圈和详情没有成本，执行一次手动压缩并确认 token 使用量更新。

### 发布门槛

- 相关 package 的定向测试和 typecheck 全部通过。
- Product CI 不再以旧版本标签禁止 Core、OpenCode、Server、Protocol 的所有改动；这些运行时包改由各自全量测试和架构依赖规则把关，以允许本轮已审查的超时、Skill 与 Worktree 修复进入发布版本。
- App 单元测试、browser tests 和新增 Playwright 回归通过。
- Desktop 构建和 Mac internal package 成功。
- Mac internal package 固定并校验可重定位 Git，安装后的应用不依赖用户预装 Git、Bun 或源码依赖；包内应用必须实际启动并完成 sidecar 就绪冒烟。
- 打包应用完成上述真实回归，没有依赖开发服务器或源码环境。
- 最终代码经过规格符合性审查、代码质量审查和独立测试审查，所有发现均关闭后才结束本目标。

## 非目标

- 不执行方案 C，不迁移整个前端状态系统。
- 不新增 Skill 安装市场或安装器。
- 不重做上下文详情布局，也不展示每次工具调用的高级统计。
- 不承诺第三方模型服务永不主动断开连接。
- 不改变 V1/V2 的服务端协议或生成客户端，除非实现过程中发现现有 API 无法提供必要的 readiness 结果；这种情况必须先重新审查设计。
